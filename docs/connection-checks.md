# 连接诊断与软件更新

[返回首页](../README.md) · [Windows 使用指南](windows.md)

## 连接诊断

进入 **设置 → 连接诊断 → 开始检测**。检测只检查当前选择的数据源与配置目录，不切换原工具账号，不创建模型会话，也不主动请求 Claude 订阅额度。

| 检查项 | 检查内容 | 发现问题后 |
| --- | --- | --- |
| 客户端工具 | 是否找到可执行文件；指定路径失效时说明实际使用的自动发现路径 | 点击「指定路径」选择已安装的官方工具 |
| 配置目录 | 目录是否存在、日志目录是否可读取 | 选择当前客户端使用的配置根目录 |
| 所选工具账号 | 使用官方工具核对所选配置目录的登录 | Claude 可进入官方登录；Codex 可打开登录指引 |
| 本机用量记录 | 是否发现支持的目录下的 JSONL 日志文件 | 正常使用原客户端后重新检测，并检查统计周期 |
| 额度数据 | GPT 官方返回的额度窗口；Claude 身份匹配且仍可展示的本地快照 | 重试或按提示启用采集 |
| 状态栏采集（Claude） | 是否配置额度转发器 | 打开采集设置，主动确认启用，再新开终端会话 |

「已发现日志」只表示存在日志文件，不表示每个版本、格式和请求都已完整解析。登录有效但额度失败时，会分别呈现结果，便于区分网络 / 接口问题与登录问题。

检测结果保留原检测时间，不会被当作业务层的实时额度或重置权限。执行诊断会使旧账号验证状态失效；之后刷新账号额度，才能重新确认敏感操作资格。账号切换或刷新后，旧诊断结果会清除。

页面可在本机显示工具路径、所选目录和邮箱，帮助核对账号是否选对；**复制脱敏诊断**只包含步骤标识、结果状态和时间，不包含这些路径、邮箱或原工具输出。不要将含个人信息的整页截图公开提交到 Issue。

## 手动检查更新

进入 **设置 → 软件更新 → 检查更新**：

- **Alpha 渠道**：接受更高版本的 Alpha / 其他预发布及正式版。
- **稳定渠道**：只查找更高的正式版本；切换渠道不会降级安装，也不会自动改装已有版本。
- 可查看版本说明，并打开当前系统对应的官方仓库下载链接。该版本尚未上传当前平台的安装包时，显示「查看版本」。
- 当前只提供检查与浏览器下载入口，不在后台下载、替换或运行安装包。

版本检查仅由用户点击触发，访问 GitHub 的公开 Releases API，不发送登录凭证、账号、配置路径、会话或用量。GitHub 仍可看到正常请求所需的网络地址和 QuotaMate 版本 User-Agent。更新说明按纯文本显示；安装链接只接受本仓库、对应版本和平台的 HTTPS 地址。响应大小和等待时间受限，限流或失败会提示稍后重试。

当前版本为 Alpha，因此不能只调用排除预发布版本的 GitHub「最新正式版」接口。[GitHub 官方 Releases API](https://docs.github.com/en/rest/releases/releases#list-releases)

## 后续顺序

此版本优先完成连接排障、Windows 常驻和版本检查。下一阶段计划：

1. 收集 Windows 真实账号、不同安装布局及缩放比例的反馈；不把 CI 虚拟环境当作全部真机兼容性结论。
2. 完善额度消耗趋势、分级提醒和恢复提醒；预测只采用可靠额度快照，样本不足时保持未知。
3. 让默认模型参考价格可以独立更新，保留手动覆盖与删除选择。
4. 对大量日志建立扫描 / 查询基准，再按实际瓶颈优化，并完善备份与迁移恢复。
5. 准备发行签名：macOS Developer ID / 公证、Windows 发布者签名。证书与发行账号由维护者提供，不将签名凭证放入公开仓库。
