# 数据来源与统计口径

## 账号额度

GPT 数据源连接的是独立 Codex CLI 的登录状态，尚未接入桌面应用内存中的当前会话。桌面切换账号不保证同步修改 CLI 登录。缓存只作为历史快照，未经本次查询确认不能标记为当前已同步账号。

自 0.1.3 起，演示模式仅在本次运行生效，忽略旧版本持久化的演示开关。启动默认读取真实数据；示例邮箱采用 demo@quotamate.example，并明确显示“演示账号”。

通过本机已经安装的 Codex App Server，调用 `initialize`、`account/read` 和 `account/rateLimits/read`。用户点击“重置额度”时，额外调用 `account/rateLimitResetCredit/consume` 消耗一份可用重置权益，再读取最新额度。后台刷新不会自动消耗重置权益。不创建 thread 或 turn，不发送模型请求；额度查询由官方工具完成，不读取钥匙串，也不保存账号凭证。服务端响应只提取账号显示信息、额度窗口、可用重置次数与采集时间。

v0.1.23 增加可关闭的自动订阅日期读取：在本机解析 Codex 登录缓存 ID 令牌的订阅日期字段，仅保留日期和来源，不使用该令牌联网、不保存或上传原始凭证。日期元数据与实时账号等级分开，不能从缓存日期推断当前订阅已过期。具体来源、身份校验和限制见 [订阅日期](subscriptions.md#自动日期来源)。

官方协议：https://learn.chatgpt.com/docs/app-server#auth-endpoints

窗口长度以返回值为准，不假定永远存在 5 小时和每周两个窗口。缺失窗口保持未知。重置时间经过后等待新数据，不能自行将剩余额度恢复成 100%。失败时保留上次成功数据并标注其状态。每个 Codex 配置目录独立查询，不改动其他工具的登录。

本机会话携带的 `rate_limits` 只作为有时间戳的历史快照，界面明确标识其来源。历史快照不触发额度通知。

## 本机历史

Claude 自 v0.1.19 接入，单独扫描所选 Claude Code 配置目录的 `projects/**/*.jsonl`。账号读取、额度采集、流式去重与缓存写入计价见 [Claude 数据源](claude-connection.md)。下文原有解析与计时区间说明针对 Codex；Claude 缺少可靠计时时保持未知，不套用 Codex 的计时事件。

扫描选定配置目录内 `sessions/**/*.jsonl` 和 `archived_sessions/**/*.jsonl`。默认目录取 CODEX_HOME，未设置时使用用户目录下的 `.codex`。只提取 `session_meta`、`turn_context`、`event_msg/token_count` 中的必要字段。每个文件保存字节游标和解析状态，下次只读取追加内容；尾部指纹检测覆盖改写；半行留到完整写入后处理。文件改写时重新建立来源关联并删除已无来源的旧记录。

SQLite 数据库只保存时间、项目路径、会话标识、模型和 token 计数，不保存用户输入、模型正文、工具调用参数和凭证。归档副本使用稳定事件标识去重。累计 token 计算增量；首次续写快照优先取 last_token_usage，避免将历史累计量重复导入。支持有明确 forked_from_id 与时间戳的复制记录归属。

统计口径为“含 token 的用量记录”，不是平台结算确认的 HTTP 请求数。因此页面采用“用量记录”“记录次数”的标签。只统计当前数据目录的本机记录，不将历史用量强行归到当前登录邮箱；其他设备、未同步到本机的云任务、已清理日志不在覆盖范围内。

当前导入器主要支持 token_count 记录，尚未单独导入部分版本的 token_usage_record 补偿事件和复杂祖先链去重；这些情况可能少计或存在归属不完整。需要更多脱敏样本才能扩大覆盖，不能当作完整账单。

## Token 与费用

统计页的缓存命中率按当前时间范围内的缓存命中 Token 合计 ÷ 输入 Token（含缓存）合计计算，不包含输出，不取逐条百分比的简单平均。显示一位小数；输入合计为零时显示 —。

统计页默认展示逐条用量明细：时间、模型、成本、新增输入、输出、缓存命中、速度、首字时间，不显示应用与供应商列。时间悬停可查看完整日期；小窗口使用横向滚动。

新增输入 = 输入（含缓存）- 缓存命中。成本仍是按用户配置单价计算的 API 等价估算。计时优先使用明确带单位的 timing 元数据；0.1.7 起也解析原生日志事件，并将推算值标记为 ≈。

首字估算：取本次请求最早的 Reasoning / AgentMessage 输出项的 item_completed.started_at_ms，减去请求起点。这里指首个模型输出项（可能是思考）的开始延迟，不是网络首字节精确测量。没有 started_at_ms 的旧记录保持未知，不用完成时间冒充首字时间。

速度估算：以用户消息、工具结果、上次用量事件等边界确定请求起点，在首次输出时固定该起点。终点优先使用用量匹配的 token_usage_record；token_count 若紧随工具结果写出，则使用最后一个模型输出项时间，尽量排除工具执行耗时。速度是输出 Token / 请求区间，含等待和思考，可能偏离服务端纯生成速度。少于 200 输出 Token、区间不超过 100ms、超过 6 小时、用量不匹配或缺少可靠边界时不显示速度。中断、新轮次和结束会清理未完成的计时状态，避免把用户停顿算入下一次请求。

计时事件选择与工具耗时处理参考 [CC Switch 的 RequestTimer](https://github.com/farion1231/cc-switch/blob/main/src-tauri/src/services/session_usage_codex.rs)，以 Dart 实现并增加游标状态持久化。上游 MIT 许可见 [cc-switch-LICENSE.txt](cc-switch-LICENSE.txt)。日志正文不保存到计时状态。

0.1.7 升级会重新扫描已有日志，为旧记录补算计时，保持原有用量记录标识去重。只补充仍保留原始日志的记录。

0.1.4 会迁移本地缓存表并重新扫描旧游标对应的原始记录，以补齐可用的计时字段；不改写原始日志。导出同步增加新增输入、缓存命中与计时列，并保留是否为估算的标记。

- 总 Token = 输入（已包含缓存）+ 输出（已包含推理）。
- 缓存、推理是子集，不再次加到总量。
- 费用 =（输入 - 缓存）× 新增输入单价 + 缓存 × 缓存单价 + 输出 × 输出单价，除以一百万。
- 默认填入已核对的五个 OpenAI 模型参考价格，详见 [价格来源与日期](reference-pricing.md)。用户可按日志中的模型名称覆盖价格；缺失任一相关模型价格时，汇总显示“未配置”。
- 订阅剩余百分比不换算为美元；估算不代表订阅实际扣费。
- 演示数据独立于真实数据库中的统计，界面和菜单栏明确标记。

## 隐私与存储

数据位于 `~/Library/Application Support/QuotaMate/usage.sqlite3`。数据库包含本机项目路径和用于显示的账号信息，应按个人数据保护。应用不包含云端服务、遥测和浏览器 Cookie 扫描。导出只包含统计字段，项目使用目录名，未包含凭证或对话正文；CSV 文本单元格做公式前缀处理。

macOS 程序采用桌面分发配置，读取用户可访问的日志目录和调用本机 CLI，因此未启用 App Sandbox。开发工具调试权限不代表生产版公证状态。正式公开分发还需要独立的开发者签名、公证、发布流程和安全审查。
